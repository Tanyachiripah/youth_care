## 5. Security & Risk Review

1. **MongoDB Atlas Network Rule (`0.0.0.0/0`):**
   - Retained unchanged per explicit deployment instruction to allow dynamic egress from Render free instances without paid static egress IPs.
   - *Status:* Accepted temporary operational risk. Connection is protected by SCRAM-SHA-256 authentication and TLS wire encryption.
2. **Database Privileges:**
   - App user `readWrite@youthcare` has access only to `youthcare`. `atlasAdmin` is not exposed or used.
3. **Session & Cookie Hardening:**
   - Cookies are configured with `HttpOnly: true`, `Secure: true`, `SameSite: "lax"`, and an 8-hour lifetime.
   - CSRF tokens are cryptographically generated and enforced on state-changing requests.
4. **Render Free Sleep Cycle:**
   - Free instances spin down after 15 minutes of inactivity; initial cold boots take 30–50 seconds.

## 6. Remaining User Activation Steps

To complete the public activation:

1. **Deploy Backend on Render (1-2 minutes):**
   - Visit [dashboard.render.com](https://dashboard.render.com/) -> **New +** -> **Blueprint**.
   - Select repository `Tanyachiripah/youth_care` (`main` branch).
   - Enter your `MONGODB_URI` secret in the secure field.
   - Click **Apply**.
   - Note the resulting Render URL (e.g., `https://youthcare-api.onrender.com`).
2. **Deploy Frontend on Vercel (1 minute):**
   - Visit [vercel.com/new](https://vercel.com/new).
   - Import `Tanyachiripah/youth_care`.
   - Set **Root Directory** to `client`.
   - In Environment Variables, set `RENDER_API_URL` to your Render URL.
   - Click **Deploy**.
3. **Set `CLIENT_URL` in Render:**
   - In Render dashboard, set `CLIENT_URL` to the assigned Vercel URL and save.
